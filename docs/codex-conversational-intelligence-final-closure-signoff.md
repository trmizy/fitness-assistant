## Original Finding (Now Fixed)

**X4 remains incomplete: completed profile confirmations disappear from the status boundary (MEDIUM).**

Independent real HTTP sequence in one session:

1. `voi tinh trang hien tai toi nen cut hay bulk?` (actual request uses Vietnamese accents).
2. Accept the proposal: DB has `UPDATE_GOAL:AWAITING_SLOT_CONFIRMATION`, goal still `MUSCLE_GAIN`.
3. `Xac nhan cap nhat.`: response acknowledges the profile update; DB goal becomes `WEIGHT_LOSS`, workflow becomes `COMPLETED`, no `FitnessAgentAction` row exists for this workflow confirmation.
4. `Da luu thanh cong chua?`: HTTP 200 says **"Chưa có thay đổi nào được lưu trong cuộc trò chuyện này"**, although the same session just successfully wrote the goal and the DB still contains that write.

Evidence: [profile-confirmation-followup.json](../test/conversational-intelligence/results/codex-final-closure/profile-confirmation-followup.json), generated by [the independent HTTP probe](../test/conversational-intelligence/codex-final-confirmation-followup.mjs). Final request trace: `ai_1790502281226_86q0du`; session `2b8b4db2-f3c4-4744-9a77-7c2c6333bd42`.

Cause: `fitness-agent.service.ts::tryConfirmationBoundary` defers only while a workflow is active, then derives history exclusively from `FitnessAgentAction`. A completed profile workflow is not an action row, so `deriveConfirmationState` returns `NONE`; `confirmationBoundaryAnswer(STATUS, NONE)` incorrectly equates no action records with no saved changes. This is a false denial of a legitimate confirmed write, not an unauthorized write and not a fabricated positive success. It falls within the requested truthful completed-state / real-profile-confirmation verification. No remediation was implemented.
