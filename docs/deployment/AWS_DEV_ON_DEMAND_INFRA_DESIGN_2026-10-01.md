### API Gateway Chat dependency (Phase 1E) — confirmed dynamic
- Route `15ai11p` (`ANY /chat/{proxy+}`) targets integration `ebe69nj`.
- Integration: `HTTP_PROXY`, `ConnectionType: INTERNET` (not a VPC Link), `IntegrationUri` = **the ALB's DNS name, hardcoded literally**: `http://fitness-assistant-dev-chat-alb-1556383256.ap-southeast-1.elb.amazonaws.com/chat/{proxy}`, payload format 1.0, 30000ms timeout.
- **Confirmed: recreating the ALB changes its DNS name** (the `-1556383256` suffix is generated per-load-balancer, not stable/predictable) — this integration's `IntegrationUri` **must** be updated whenever the ALB is recreated, or Chat traffic silently breaks even though the API Gateway route itself looks unchanged.
- Also confirmed live: the **real application source** hardcodes this exact same ALB DNS name — `frontend/web/.env.production` and `.env.production.example`, both `VITE_CHAT_WS_URL=http://fitness-assistant-dev-chat-alb-1556383256.ap-southeast-1.elb.amazonaws.com`. Since Vite env vars are compile-time, **the frontend bundle itself needs a rebuild+redeploy**, not just a backend config change, if the ALB is ever recreated with a new DNS name. This is a real, source-level `DYNAMIC_RECREATE_ID` dependency, not just an infra one.
