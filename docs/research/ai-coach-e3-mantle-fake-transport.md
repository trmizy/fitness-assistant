## Implementation

`src/evaluation/bedrock-pilot/mantle-transport.ts` adds a pure text-only serializer and an explicitly injected **FAKE** IO adapter. Fixed target: `anthropic.claude-haiku-4-5`, Ohio `us-east-2`, `https://bedrock-mantle.us-east-2.api.aws/anthropic/v1/messages` and its `/count_tokens` sibling. Header: `anthropic-version:2023-06-01`. No HTTP client, credentials, signer or retry client is constructed; Runtime/Converse/Global cannot be selected by this adapter.

One canonical token-bearing object contains `model`, text `system` blocks and `messages`. The count body is that object. Inference adds generation-only `max_tokens` and at most one sampling setting. The entire shared projection is byte-identical after removing those generation-only fields. Count does **not** receive unsupported `max_tokens`/sampling fields. Tools, media, cache, thinking, native output schema and unknown request fields are rejected rather than omitted from counting. Contracts: [AWS Mantle counting](https://docs.aws.amazon.com/bedrock/latest/userguide/count-tokens.html), [AWS Messages](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-messages-api.html), [Anthropic count schema](https://platform.claude.com/docs/en/api/messages/count_tokens).

The old Converse-shaped TypeScript input/output types remain an **internal compatibility DTO** around the existing session. Wire requests use Anthropic Messages exclusively. Normalization retains the complete redacted native provider reply beside the normalized text/usage; no claimLinks are projected away. Native id/model/metadata and error replies remain available under canonical redaction receipts. Count replies are retained even when preflight rejects an over-cap count. Existing E2 schema, grounding, annotation/blinding, R1 receipts and D1/D2/D3 implementations are unchanged.

Responses must have valid non-stream message/text structure, an allowlisted Haiku identifier, `end_turn` and integer usage. Refusals, truncation, tool/thinking blocks, unknown usage and unsupported response features fail closed. Nonzero cache usage is rejected: ordinary `input_tokens` alone would exclude cache reads/writes, so treating it as total would undercount. [Anthropic cache accounting](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

Session reserves output/spend before dispatch. Missing/mismatched usage stops immediately and retains the conservative reservation. Ordinary provider/JSON failures stop at2, without retry. Invalid native replies preserve their redacted raw response even if they cannot be scored; conservative reservations may remain even when an invalid reply contains usage. A valid token count is not evidence that the answer is scientifically correct.

Optional `transportProtocol:"MANTLE_MESSAGES"` requires the exact bare model/Ohio/null-profile target, FAKE mode, no live opt-in/approval, FAKE pricing, E2 contract and R1-only mode. Protocol caps cannot exceed **8 calls, USD1, 12,000 input/call, 2,048 output/call, 96,000/16,384 total tokens, retries0, failures2**. Design stays two arms, MINIMAL, two repeats. Runner requires exactly two prepared clusters/eight rows before counting. The separate intake admission13,000 cap is never reused. Existing generic configurations remain unchanged when the new protocol is absent.

Actual CAL01/CAL06 inputs and their owner-reviewed provenance remain private/pinned. This task does not run that real warmup bundle,20 frozen owner clusters or183 variants. Tests use synthetic inputs representing the two calibration slots. Existing related regression may exercise its own synthetic fixtures; none grants an actual dataset release.
