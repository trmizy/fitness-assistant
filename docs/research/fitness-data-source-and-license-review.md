## Legal categories tracked per source

Per the task's requirement, code / database / text / image / video / 3D-model
license are tracked **separately** — a repository's top-level license badge
almost never covers all of these uniformly, and treating it as if it does is
exactly the mistake this review exists to avoid.

## What this means for the current gaps

- **Exercise data (Phase 1)**: the app's existing `exercises` table (883 rows) is 100% free-exercise-db-derived (English only, license-clean text, license-murky images already hotlinked — a pre-existing issue). The already-curated, NOT-yet-imported `data/catalog/plans/gym_exercises.csv` (205 bilingual entries, `source_type: curated_vi` per its own design doc) is **original content authored for this project** — no external-license question applies to it at all; it is the fastest, lowest-risk path to Vietnamese-named exercises, and is addressed in the impact map / Gate 3+ plan rather than a fresh wger bulk-import being the first move.
- **wger** is confirmed usable as a **secondary, gap-filling** bulk exercise source (not primary) — real per-entry license data now confirmed available via its live API, which any importer must actually read and store, not assume.
- **Muscle-map SVG (Phase 1)**: `body-muscles` (Apache-2.0) is the clear pick; Z-Anatomy is documented per the task's requirement but not recommended for this phase.
- **Nutrition (Phase 3)**: USDA (already in use, safe) stays the backbone. Open Food Facts needs a runtime-lookup-first product decision before any bulk import. The FAO Vietnamese table — the most directly relevant source for "món ăn Việt Nam" — is blocked on a license confirmation this review could not complete (network access to FAO's own pages was refused); until resolved, Vietnamese-dish nutrition work should proceed via the recipe-from-ingredients model (USDA-sourced ingredients composed into Vietnamese recipes, e.g. phở bò from its component ingredients) rather than importing the FAO table wholesale.
